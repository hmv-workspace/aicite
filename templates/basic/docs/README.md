## How this project works

This repo runs docs-as-code. The documents in this folder are the recipe; the agent is the machine that executes it.

- **Humans own intent and outcome** — what to build, how it should be designed, what "done" means, and whether the end product is right. That is decided by people and recorded here.
- **Agents own the logistics** — reading these docs, writing code that satisfies them, running the test plan, keeping status current, and reporting progress or blockers.
- **Docs lead code.** A change starts as a doc change. Where code and docs disagree, one of them is wrong — raise it, don't paper over it.
- **No silent invention.** If it isn't in the docs, the agent asks. An agent never decides a requirement on its own.

The rules agents follow are in [`AGENTS.md`](../AGENTS.md) at the repository root.

## The Workflow

Run this cycle with your AI assistant:

1. **Define (WHAT)** — open [requirements.md](./requirements.md) and describe the feature. Ask your agent to help refine it.
2. **Design (HOW)** — open [architecture.md](./architecture.md) and plan the approach. Ask your agent to review it for scalability and security.
3. **Plan (HOW)** — open [development.md](./development.md) and settle the technical details (APIs, schema, code structure). Then: *"Implement this based on the requirements, architecture, and development plan in `docs/`."*
4. **Verify (WHAT to check)** — open [testplan.md](./testplan.md) and define the test cases (guardrail tests get a `TC-xxx` ID). Ask your agent to write or run tests against them.
5. **Track** — your agent reports what it ran and what is outstanding; you confirm completion and the status moves to ✅. Agents mark progress (🔄) and blockers (⚠️) themselves, never ✅.
